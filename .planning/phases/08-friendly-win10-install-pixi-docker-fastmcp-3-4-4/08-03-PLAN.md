<objective>
Adopt FastMCP 3.4.4 feature F5 (D-04): a `TimingMiddleware` that records per-tool-call duration
and success/failure into the existing `MetricsCollector`, registered in `create_server`.

Purpose: centralize tool-call timing at the middleware layer (the hot path) as the incremental
first step of migrating the executor's imperative timing (CONTEXT §7 default: add middleware,
migrate later — do NOT big-bang rewrite the executor this pass). Output: new
`src/matlab_mcp/middleware/` package + registration + tests.

CRITICAL API NOTES (verified against the real code, the RESEARCH sketch is imprecise):
- `MetricsCollector.record_event` signature is `record_event(event_type: str, details: dict)` —
  NOT the kwargs form in the RESEARCH F5 snippet.
- The executor ALREADY records `job_completed`/`job_failed` with `execution_ms` for executed
  jobs. To avoid double-counting job totals, the middleware records a DISTINCT event type
  (e.g. `"tool_call"`) with `{"tool": <name>, "duration_ms": <ms>, "success": <bool>}`; that
  event type is not in `_COUNTER_MAP`, so it is a clean additive store write.
</objective>
